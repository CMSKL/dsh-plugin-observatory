# 设计：插件兼容性审计与生命周期观测

Status: implemented

[English](design.md) | 中文

## 问题

DSH 插件是可安装的 Cordis 组合，但插件作者缺少一项产品内检查，用来判断本地包是否声明了可加载的 DSH bundle，是否匹配当前 DSH、Cordis 与 Node 版本，以及运行时依赖名称是否正确。运行时检查可以显示当前 Loader 状态，却不保留能够解释某个条目为何持续 pending、变为 active、失败或卸载的转换历史。把它做成独立服务会让插件开发依赖另一套部署，还会重复 Harness Loader 对当前状态的权威职责。

## 决策

**产品单元是一个独立、可安装的 DSH bundle。** `dsh-plugin-observatory` 位于官方 Harness 仓库之外，通过 `dsh.bundle` 补丁挂载 `PluginObservatoryService` 及本包拥有的 invariant companion。服务位于 `ctx.pluginObservatory`；`plugin_audit` 与 `plugin_observe` 是通过 `ctx.tools` 注册的只读消费方。未来的 CLI（命令行界面）、CI 报告器或 Web 界面消费同一服务，而不拥有另一套兼容性实现。

**静态审计绝不激活目标包。** `audit(packagePath, cwd, signal?)` 只读取 `package.json` 及其中声明的 bundle 补丁。两个文件都有可配置的字节上限，必须是有效 UTF-8；路径经过规范化，并且符号链接解析后必须仍位于允许的根目录之下。解析后的图还有可配置的深度与节点访问预算；路径级祖先集合会拒绝循环 YAML alias，同时允许普通 alias 复用。补丁使用 Loader include 包导出的 DSH YAML schema，因此 `!!js` 值会变成惰性的表达式记录。审计器会记录这些表达式，并标记环境访问或动态加载语法，但绝不求值表达式，也不导入包内 JavaScript。

**报告区分兼容性错误与人工复核项。** 版本为 `1` 的报告按确定顺序排列检查项，并且不含时间戳。无效 manifest、缺失 bundle 声明、不安全的包内相对路径解析、循环或超预算 patch 图、未声明的运行时包，以及不满足的受支持版本范围会产生 `incompatible`。安装生命周期脚本、缺失的描述性元数据、读取环境或执行动态加载的表达式，以及无法解释的版本范围会在没有错误时产生 `needs-review`。服务在激活时采集一次宿主版本：CLI 版本可用时以它为准，否则使用一致的 DSH 发行族版本；版本不可用或冲突会成为明确的复核项。报告还会提取所插入条目、目标 id 与表达式，让后续消费方无需再次解析补丁即可解释结果。

**Loader 仍是当前状态的权威。** 服务在每次快照时读取 `ctx.loader.entries()`，只保存服务激活后观测到的、有界的根 fiber `internal/status` 进程内历史。group 条目与子 fiber 会被排除。每个条目的上限与条目总数上限都由部署配置；达到总数上限时，淘汰最久没有转换的历史。invariant companion 检查每个已投递的根 fiber 状态事件是否与最新保留转换一致。

## 曾考虑的替代方案

**先构建独立插件市场或评测服务器。** 不采用：第一批有用能力是本地分析与 Loader 观测，两者都属于正在运行的 Harness。独立部署会先增加认证、存储与同步工作，却还没有改善插件正确性。

**只复用既有 Host 插件清单。** 不采用：该 Remote 刻意只提供调用时点的 UI 清单，不提供历史、包源码访问、兼容性检查项或模型可见工具。扩展它会把窄范围的 client 投影与插件作者诊断混在一起。

**在兼容性审计期间安装并执行目标包。** 不采用：包安装与任意插件激活会引入预安装静态检查不需要的副作用和权限。执行冒烟测试仍属于之后需要显式沙箱化的评测阶段。

**在第一个包中持久化观测与评测运行。** 不采用：生命周期转换目前是诊断性进程状态，而可复现任务集与评分卡需要单独的运行产物设计。执行阶段尚不存在时就添加持久化，会过早选择标识符与格式。

## 后果

插件作者可以安装一个 DSH 原生 bundle，并让正在运行的 agent（智能体）审计本地插件或检查近期 Loader 转换。对于相同文件和宿主版本，兼容性输出可以复现；运行时观测则刻意携带时间戳并且只在进程内存在。服务 API 为下一阶段提供稳定的复用点：隔离安装与冒烟执行、可复现任务集、基线对比、CI 策略和 Web 评分卡都能作为消费方加入，而无需把审计引擎移出 DSH。registry 与 GitHub 发现、传递代码信任、沙箱化执行、持久化运行产物，以及按插件归因的工具延迟或 token 用量仍明确暂缓。
